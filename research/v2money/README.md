# Бумажные боты V2 (только данные, без ключей и ордеров)

Два процесса для круглосуточной бумажной проверки. Ключи не нужны, ордера не отправляются.

Результаты бумажных тестов — [RESULTS.md](RESULTS.md).

**С 0.28.0 основной инструмент проверки — стол агентов Vespera** (Агенты → V2, агенты a9 и a10). Он ведёт
`latarb_v2` и `lp_v1` с Addendum C круглосуточно на живых потоках, со своим бумажным счётом в масштабе планов,
и сам считает сертификаты по дополнениям для стола (Desk addendum в [latarb_v2.md](latarb_v2.md) и
[lp_v1.md](lp_v1.md)); см. [AGENTS](../../docs/AGENTS.md#v2-отдельный-счёт-и-сертификаты). Боты этой папки
остаются для исследований и сверки; их результаты в сертификат стола не входят.

| Файл | Что делает |
|---|---|
| `latbot.js` | Латентный арбитраж BTC/ETH Up/Down 5m и 15m. Правило `latarb_v1` (заморожено 2026-11-05 01:20 UTC): скачок Binance за 1 с больше 2 б.п. → виртуальная покупка стороны скачка по лучшему ask CLOB, каким он был через 150 мс по серверному времени. Размер ≤ 100 акций, комиссия 0,07·p·(1−p). Оценка: середина через 10 с, выход по bid через 10 с с двумя комиссиями, итог окна. ETH — контроль. |
| `lp_universe.js` | Вселенная для LP: рынки с наградами ≥ $5 в день, без спорта, до конца ≥ 3 дней, середина 0,10–0,90. Берёт 300 рынков с лучшей ожидаемой отдачей на капитал. |
| `lp_paper.js` | Бумажный LP с перекотировкой раз в 10 с. Варианты `g` и `h`. Исполнения: сделки RTDS по нашей цене или сквозь неё, плюс пересечение стакана. Награды считаются по формуле Polymarket раз за опрос, доля — пессимистичная и агрессивная. |
| `report_lat.js`, `report_lp.js` | Сводки. |
| `addB.py` | Addendum B: фильтр тишины по журналу латентного бота (`python3 addB.py out`). |
| `lp_reality.py` | Сверка экономики LP с реальными кошельками по публичной статистике Data API v2. |
| `maker_updown/` | Мейкер на крипто Up/Down (отвергнут): `load2.py` готовит данные коллектора, `mm_sim2.py` и `mm_pick2.py` — симуляции. |
| `smart_money/` | «Умные деньги» (отвергнуто): выборка кошельков, их P&L и цены, проверка копирования. |
| `kalshi/` | Kalshi × Polymarket: `scan.py` сканирует раз в 2 мин, `gaps.py` считает разрывы. |
| `ops/watchdog.js` | Сторож 24/7: живы ли боты, свежи ли их файлы и потоки, опционально — Telegram. |
| `ops/reconcile.js` | Сверка журнала с публичными данными кошелька: сделки, позиции, награды и ребейты по дням. |
| `ops/skeptic.py` | Проверки скептика: кластерный t, бутстрэп, часы, концентрация, Deflated Sharpe. |

Запуск (нужен Node ≥ 22):

```bash
./run.sh start    # запустить оба процесса
./run.sh report   # сводка
./run.sh stop     # остановить
./run.sh check    # проверка сторожем, один раз
./run.sh watch    # сторож раз в минуту в фоне (unwatch — остановить)
```

Сторож пишет одну строку JSON на проверку; код выхода 1 — что-то не так. `COLLECTOR=` и `LANES=` добавляют
проверки коллектора и полос стола агентов (`userData/agents/lanes`). С переменными `TELEGRAM_BOT_TOKEN`
и `TELEGRAM_CHAT_ID` он присылает в Telegram новые проблемы и сообщает, когда они ушли.

Все гипотезы и число перебранных вариантов — в [REGISTRY.md](REGISTRY.md).

Данные пишутся в `out/` (сделки латентного бота) и `lpout/` (состояние и журналы LP).
Перезапуск продолжает с сохранённого состояния.
Перекотировка LP по умолчанию раз в 10 с; `POLL_MS=3000 ./run.sh start` — раз в 3 с (в тестах лучше, но запросов к API больше).

Критерии зачёта (заранее заданы):

- Латентный арбитраж: ≥ 2000 бумажных сделок по BTC. Перевес через 10 с > +3¢ на акцию при t > 3,
  выход через 10 с > 0, итог окна > 0.
- LP: ≥ 24 ч, затем подтверждение ещё 24 ч на свежей вселенной. Итог (награды по пессимистичной доле
  плюс переоценка) > 0, ни один рынок не даёт больше 25% итога.

## Критерии теста
`latarb_v2.md` — план 24/7-фазы, зафиксирован до новых данных. Основной рынок — BTC 5m, метрика — выход по bid через 10 с с двумя комиссиями. Сертификат: ≥ 2000 сделок BTC (из них ≥ 1000 BTC 5m), p < 0,01, итог окна > 0, ни один день не даёт > 50 % P&L, ≥ 70 % полных дней в плюсе. `latarb_v1.md` — предыдущий план латентного арбитража, `lp_v1.md` — план LP (с Addendum A–C). Как стол агентов
читает `latarb_v2.md` и `lp_v1.md` (полные дни, фазы, тени, масштаб) — в их Desk addendum.
