# Импорт программы в EcoStruxure Machine Expert

Файлы в этой папке:

| Файл | Назначение |
|---|---|
| `EFBSH-649_PLC.xml` | вся программа (16 типов, 5 списков переменных, 15 программ/ФБ/функций) в формате PLCopenXML |
| `map_io.py` | скрипт автоматической привязки 299 каналов к переменным `GVL_IO` |
| `../doc/IO_map.csv` | таблица каналов для проверки и ручной привязки |
| `../doc/HMI_map.md` | регистры Modbus для проекта панели Weintek |

Проверено для Machine Expert 2.x (CODESYS V3.5). Файл `.project` напрямую не создаётся: это закрытый формат,
поэтому контроллер и модули добавляются в Machine Expert вручную (около 5 минут), а программа импортируется целиком.

## 1. Создать проект и конфигурацию

1. Файл → Создать проект → **Пустой проект** (или «Стандартный проект» с контроллером), имя например `EFBSH-649`.
2. Добавить контроллер **TM241CE40T** (Логические контроллеры → M241).
3. В дереве устройств правой кнопкой по **IO_Bus** → Добавить устройство, строго в порядке Э3:
   - 7 шт. **TM3DI32K** (A1.1 … A1.7),
   - 2 шт. **TM3DQ32TK** (A1.8, A1.9).
4. Ethernet_1: задать IP-адрес контроллера по проекту. Modbus TCP сервер M241 включен по умолчанию,
   регистры `%MW` доступны панели с порта 502.

## 2. Импортировать программу

1. Выделить в дереве узел **Application**.
2. Проект → **Импорт PLCopenXML…** → выбрать `EFBSH-649_PLC.xml`.
3. В окне импорта оставить все галочки → ОК. Если спросит о совпадающих именах (например, `POU`, `GVL`
   из шаблона) — **Заменить**.
4. Объекты появятся в папках DUT, GVL, POU.

## 3. Задача

Открыть **Task Configuration → MAST**: тип «Циклическая», интервал **20 мс**. В списке вызовов оставить
только **PLC_PRG** (удалить вызов `POU` из шаблона, если он был, и сам объект `POU`).

## 4. Привязать входы и выходы

Вариант А — скриптом:

1. Инструменты → Скрипты → **Выполнить файл сценария…** → `map_io.py`.
2. Скрипт ничего не меняет, только выводит план в окно «Сообщения»: какой канал к какой переменной
   будет привязан. Проверить несколько строк по `IO_map.csv` (например, `DI` I0 → `DI_SYS_ON`, `DQ` Q0 → `DO_SIREN`).
3. Если план верный — открыть `map_io.py` в блокноте, заменить `APPLY = False` на `APPLY = True`,
   запустить ещё раз, сохранить проект.
4. Если какой-то модуль скрипт пропустил («число каналов не совпадает») — привязать его вручную (вариант Б).

Вариант Б — вручную: двойной щелчок по DI, DQ и каждому модулю → вкладка **Соотнесение входов/выходов** →
в колонке «Переменная» для канала ввести `Application.GVL_IO.<имя>` по таблице `IO_map.csv`
(колонки «Модуль», «Канал», «Переменная GVL_IO»).

## 5. Компиляция и загрузка

1. Компиляция → **Построить** (F11). Ожидается 0 ошибок; предупреждения о неявном преобразовании типов допустимы.
2. Онлайн → Подключиться → загрузить → Старт.
3. При первом запуске уставки заполняются значениями по умолчанию (задержки пуска/останова и т.д.),
   дальше они хранятся в RETAIN и меняются с панели.

## Если при компиляции есть ошибки

Программа проверена синтаксическим анализатором и исполнением в симуляторе (все 11 маршрутов, аварии,
режимы), но на реальном компиляторе Machine Expert не собиралась. Если появятся ошибки — пришлите
текст из окна «Сообщения» (или снимок экрана), исправлю.
