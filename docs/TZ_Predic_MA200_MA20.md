# Техническое задание
## Автобот Predic: ставки на следующую свечу BTC по MA200 / MA20

**Версия:** 1.0  
**Дата:** 14.09.2026  
**Источники:** видео-разбор графика (IMG_6140.MOV, ~2:17), транскрипт, переписка Ilias ↔ исполнитель 13.09.2026  
**Платформа ставок:** Predic (русский аналог Polymarket, появился API)  
**Первый релиз:** только Bitcoin, таймфрейм 15 минут, полностью автоматическая торговля

---

## 1. Цель продукта

Отдельное десктоп-приложение, которое:

1. Считает скользящие средние **MA200** и **MA20** по выбранному графику.
2. Находит паттерн «откат к MA20 в сторону тренда MA200».
3. В момент закрытия сигнальной свечи **само** покупает по маркету исход «следующая свеча продолжит направление».
4. Если ставка не зашла — ищет **следующий такой же паттерн** и ставит **в 2 раза больше**, максимум **6 попыток** подряд.
5. Имеет режим отладки, где сделки не открываются, а только рисуются точки входа.

Бот **не зависит от того, какой график открыт у пользователя в браузере**. Таймфрейм и инструмент задаются в настройках приложения. Расчёт идёт по своим котировкам. График TradingView в окне — визуализация, а не источник истины для ордеров.

---

## 2. Что такое Predic в этом проекте

Predic работает **не как фьючерс с плечом**, а как **бинарная ставка** (как Polymarket):

- На рынок вида: «BTC на следующем интервале закроется **выше** / **ниже**».
- Покупаешь исход **по маркету** на фиксированную сумму (в видео: 1 $, потом 2 $).
- Если цена в нужную сторону относительно страйка/ставки — ставка заходит, выплата фиксированная.
- Если нет — ставка сгорает. Ликвидации как на фьючерсах нет, риск = размер ставки.

**Следствия для бота:**

- Нет SL/TP в классическом смысле. Результат известен после экспирации рынка (закрытие свечи / конец раунда).
- «Открыться в лонг» = купить исход **UP / выше**.
- «Открыться в шорт» = купить исход **DOWN / ниже**.
- Ордер только **market**, сразу, без лимитки.
- Одновременно в v1 — **один инструмент, один рынок, одна активная ставка**. Не 200 рынков сразу (это прямой ответ на вопрос про корреляцию и ликвидацию).

Точный бренд/домен API на момент ТЗ заказчик назвал «Predic / предди». Перед кодом нужен рабочий ключ и ссылка на docs. Логику ордера закладывать через адаптер `ExchangeAdapter`, чтобы сменить хост без переписывания стратегии.

## 4. Индикаторы

На графике две линии, как в видео:

| Линия | Период | Цвет в видео | Роль |
|---|---|---|---|
| Медленная | MA 200 | синяя / голубая | фильтр тренда |
| Быстрая | MA 20 | красная | триггер входа |

### 4.1. Формула (зафиксировать, иначе бэктест разъедется с TradingView)

- Тип: **SMA** (простое среднее). Если на эталонном графике заказчика стоит EMA — переключить одним флагом в настройках. По умолчанию SMA, потому что в речи «скользящие средние», без слова EMA.
- Источник: **close**.
- Смещение: 0.
- Расчёт на **закрытых** свечах. Текущая формирующаяся свеча **не даёт сигнал**.

```
MA20[i]  = mean(close[i-19 : i])     // i — индекс закрытой свечи
MA200[i] = mean(close[i-199 : i])
```

Нужно минимум 200 закрытых баров выбранного ТФ до старта торговли. Если истории меньше — статус `warming_up`, ордеров нет.

### 4.2. Независимость от «какого графика смотришь»

Пользователь может открыть 1m, 1h, 1D в TradingView-виджете. Стратегия считает **только выбранный в настройках рабочий ТФ** (v1 = 15m). Смена ТФ в виджете не меняет логику ставок, пока её не сменили в настройках.

## 5. Торговая логика

Ниже — каноническая формулировка после уточнений Ilias (10:10, 13.09.2026), сверенная с видео.

### 5.1. Фильтр тренда (MA200)

Берём **закрытую** свечу `S` (сигнальную).

- Если `close[S] > MA200[S]` → разрешены **только лонги** (ставка UP).
- Если `close[S] < MA200[S]` → разрешены **только шорты** (ставка DOWN).
- Если `close[S] == MA200[S]` → нет входа.

Это жёсткий фильтр. Лонг ниже 200-й и шорт выше 200-й **запрещены**, даже если MA20 пересекли.

### 5.2. Триггер (MA20 + цвет закрытия)

На той же закрытой свече `S` должно произойти **пересечение MA20**.

**Пересечение вверх (кандидат в лонг):**

```
low[S]  <= MA20[S]   И   close[S] > MA20[S]
```

Дополнительно свеча `S` **зелёная**: `close[S] > open[S]`.

**Пересечение вниз (кандидат в шорт):**

```
high[S] >= MA20[S]   И   close[S] < MA20[S]
```

Дополнительно свеча `S` **красная**: `close[S] < open[S]`.

Додж (`close == open`) — не вход.

### 5.3. Полные условия входа

**LONG (ставка UP на следующую свечу), все пункты обязательны:**

1. Свеча `S` закрылась.
2. `close[S] > MA200[S]` — цена выше 200-й (как в видео: «выше синей и выше красной»).
3. Свеча `S` пересекла MA20 снизу вверх (п. 5.2).
4. Свеча `S` зелёная.
5. Нет уже открытой ставки на текущий раунд.
6. Серия мартингейла < 6 неудач подряд (см. §6).
7. Режим Auto + нажато Start.

**SHORT (ставка DOWN), все пункты обязательны:**

1. Свеча `S` закрылась.
2. `close[S] < MA200[S]` — цена ниже 200-й.
3. Свеча `S` пересекла MA20 сверху вниз.
4. Свеча `S` красная.
5–7. Те же ограничения, что у лонга.

В видео отдельным жестом показан **откат**: цена сначала ушла за MA20 против тренда, потом пересекла её обратно. Формула пересечения в п. 5.2 это покрывает: чтобы пересечь MA20 вверх, свеча должна задеть линию снизу (часто после захода под красную). Отдельную «предыдущую свечу обязательно под MA20» **не требуем**, если заказчик не настоял — иначе отфильтруем часть его же примеров. Если при приёмке скажет «нужен явный заход под 20-ю на предыдущей свече», добавляется флаг `require_prior_penetration = true`:

```
LONG extra:  low[S-1] < MA20[S-1]
SHORT extra: high[S-1] > MA20[S-1]
```

По умолчанию в v1 флаг **выключен**.

### 5.4. Что бот ставит

Сигнал считается **на закрытии `S`**. Ставка ставится **на следующую свечу `S+1`**.

Смысл (слова заказчика): «бот должен ставить на продолжение тренда в следующей свече».

| Сигнал | Покупка на Predic | Смысл |
|---|---|---|
| LONG | market YES / UP | следующая 15m свеча закроется выше страйка |
| SHORT | market NO / DOWN | следующая 15m свеча закроется ниже страйка |

Страйк = цена, от которой Predic считает «выше/ниже» для этого раунда (обычно цена на открытии раунда / в момент создания рынка). Бот **не выбирает страйк** — берёт текущий открытый рынок BTC 15m.

### 5.5. Момент исполнения (критично)

Порядок на закрытии 15m свечи:

1. Дождаться **канонического close** рабочего ТФ (время свечи кратно 15 минутам, биржа-источник котировок).
2. Пересчитать MA20/MA200.
3. Если паттерн есть — в течение **не более 3 секунд** отправить market-ордер в Predic на рынок **текущего / только что открывшегося** 15m-раунда.
4. Если рынок раунда уже закрыт для входа — **пропустить**, не догонять следующий раунд без нового паттерна.
5. Не ставить «на ту же свечу, которая ещё рисуется».

Расхождение часов ПК и биржи: синхронизация NTP, рабочее время — Unix UTC. Свечи 15m: `:00, :15, :30, :45`.

### 5.6. Что не является входом (из видео)

Заказчик явно пропустил сетап: пересечение красной было, «по идее следующая должна быть шортовая, но тут она не шортовая. Ищем следующий вариант».

Это не отдельное правило «смотреть цвет следующей». Это значит:

- вход только по правилам 5.3 на **закрытой** свече;
- если правила не выполнены — **ждём следующий бар**, серию мартингейла не трогаем;
- мартингейл увеличивается **только после проигранной ставки**, а не после пропущенного сетапа.

### 5.7. Псевдокод

```
on_bar_close(bar S):
    if not running: return
    if bars_ready < 200: return
    if has_open_bet: return
    if martingale_step > 6: wait_reset(); return

    ma20  = SMA(close, 20)
    ma200 = SMA(close, 200)

    long_ok  = close[S] > ma200[S] and crossed_up(S, ma20)  and is_green(S)
    short_ok = close[S] < ma200[S] and crossed_down(S, ma20) and is_red(S)

    if long_ok:
        place_market(side=UP,   size=base_usd * 2^(step-1), market=btc_15m_next)
    elif short_ok:
        place_market(side=DOWN, size=base_usd * 2^(step-1), market=btc_15m_next)
```

## 6. Управление капиталом (мартингейл)

Зафиксировано Ilias: «если не зашел то бот 2ой такой патер ишешь и в 2 раза больше уже ставишь , до 6 раз можно увеличивать ставку».

| Попытка | Размер при base = 1 USD |
|---|---|
| 1 | 1 |
| 2 | 2 |
| 3 | 4 |
| 4 | 8 |
| 5 | 16 |
| 6 | 32 |
| после 6-й проигрыша | стоп серии, **не** ставить 64 |

Максимальный риск одной серии при base=1: **1+2+4+8+16+32 = 63 USD**.

Правила:

1. Серия общая, **без разделения long/short**. Проиграл лонг на 1$ → следующий паттерн (даже шорт) ставится на 2$.
2. Выигрыш **сбрасывает** шаг на 1, размер снова `base_usd`.
3. Пропуск паттерна (условия не сошлись) шаг **не меняет**.
4. После 6 проигрышей подряд: статус `martingale_halt`. Новых ордеров нет, пока пользователь не нажмёт Start заново или в настройках не включит `auto_reset_after_halt`.
5. Нельзя открыть вторую ставку, пока не рассчитана предыдущая.
6. Перед ордером проверка баланса Predic ≥ size + комиссия. Если нет — не ставить, лог `insufficient_balance`, серию не увеличивать.

База, максимум попыток, флаг автосброса — в настройках.

## 7. Режимы работы

### 7.1. Auto

- Start: стратегия живая, ордера уходят на Predic.
- Stop: новые ордера не слать. Уже открытая ставка **доживает** до экспирации, результат пишется в журнал. Stop не пытается «отменить бинарный раунд», если API это не умеет.
- На графике: стрелки входов, подпись размера и стороны, результат (win/loss) после экспирации.

### 7.2. Debug / отладка

- Тот же алгоритм, **ноль ордеров**.
- Рисует те же точки, пишет виртуальный PnL и виртуальный мартингейл.
- Нужен, чтобы заказчик сверил стрелки с тем, что он тыкал пальцем на видео, без риска денег.

Переключение Auto ↔ Debug на работающей серии: виртуальный и живой мартингейл **не смешивать**. При смене режима шаг сбрасывается в 1, если не подтверждено «продолжить серию».

```
├──────────────────────────────────────────────────────────┤
│                                                          │
│              TradingView виджет (~90% окна)              │

└──────────────────────────────────────────────────────────┘
```

- Окно графика тянется, занимает основную площадь.
- Сверху справа: настройки.
- В настройках обязательные пункты:
  - API Predic (ключ / секрет / кошелёк — что выдаст площадка);
  - инструмент (v1: BTC, список расширяемый);
  - таймфрейм;
  - base USD, max steps (1–6);
  - Auto / Debug;
  - источник котировок для MA (Binance / Bybit / тот же оракул, что у Predic — см. открытые вопросы).
- Кнопки Start и Stop всегда на виду, не спрятаны в меню.
- Статусы: `stopped` / `warming_up` / `watching` / `order_sent` / `waiting_settlement` / `halt`.

Маркеры на графике:

- LONG — стрелка вверх под свечой `S`, подпись `UP $N`;
- SHORT — стрелка вниз над свечой `S`, подпись `DOWN $N`;
- после расчёта цвет маркера: зелёный win / красный loss.

## 9. Данные и интеграции

Разделить два потока. Их нельзя путать.

### 9.1. Котировки для MA (сигнал)

Нужны OHLC выбранного ТФ в реальном времени.

Рекомендация v1: публичный REST/WS той биржи, чей BTC ближе к оракулу Predic (часто Binance BTCUSDT). Иначе MA на TV и исход ставки будут считаться по разным ценам.

Требования:

- WS-лента + реконнект;
- закрытие бара по биржевому timestamp, не по таймеру ПК;
- хранить ≥ 500 баров локально;
- при дыре в истории — догрузить REST, не считать MA по дырявому ряду.

### 9.2. Predic API (исполнение)

Минимальный набор методов адаптера:

- авторизация;
- баланс;
- найти **текущий открытый** рынок `BTC 15m up/down`;
- market buy YES или NO на сумму N;
- статус позиции / ставка принята;
- результат раунда после экспирации (win/loss, payout);
- опционально: история ордеров.

Ошибки API (таймаут, 429, insufficient, market closed) — в лог, ордер не считается исполненным, мартингейл не шагает.

Идемпотентность: `client_order_id = f"{date}-{tf}-{bar_open_ts}-{side}-{step}"`. Повторная отправка того же id не должна открыть вторую ставку.

### 9.3. TradingView в UI

Только отображение. Не парсить DOM TV и не читать оттуда MA. Оверлей маркеров — своими объектами поверх виджета или через `tvWidget` chart API, если доступен. Если встроить маркеры в TV нельзя стабильно — дублировать упрощённый свой график под виджетом с теми же стрелками. Для приёмки достаточно, чтобы заказчик видел точки на том же BTC 15m.

## 12. Приёмка (по видео и чату)

Демо в Debug на BTC 15m, затем 1 ставка Auto по $1.

1. На экране две линии: красная MA20, синяя MA200.
2. Выше 200-й появляются **только** стрелки LONG, ниже — **только** SHORT.
3. Стрелка стоит на свече, которая **пересекла красную** и закрылась в сторону сделки (зелёная = long, красная = short).
4. Ставка уходит **сразу по маркету** после закрытия этой свечи, не по кнопке пользователя.
5. Проигрыш → на следующем валидном паттерне размер ×2.
6. Выигрыш → размер снова база.
7. 6-й проигрыш подряд → бот молчит, пока не Start.
8. Stop прекращает новые ставки.
9. Debug не шлёт ордера, но рисует те же точки.
10. Смена ТФ в виджете TV не ломает 15m-логику.

Разбор из видео ( qualitatively, для сверки с историей):

- Лонг: цена выше синей, укол/заход под красную, затем пересечение обратно вверх зелёной свечой → ставка UP $1 на следующую, заход.
- Пропуск: пересечение красной было, но полные условия шорта не сложились → нет ставки.
- Шорт позже: пересечение красной вниз при положении под синей → DOWN $2, заход.

Если на истории Debug стрелки стоят не там, где заказчик водил пальцем — сначала правим правила, не ордерный шлюз.

## 13. Открытые вопросы (закрыть до кода исполнения)

Помечены как **блокер**, если без ответа нельзя безопасно слать деньги.

1. **Блокер.** Точный URL кабинета Predic + docs API + тестовый ключ. Название в речи («предди») пересекается с predict.fun / predifi / другими. Адаптер писать после 1 успешного ручного market-ордера через тот же ключ.
2. **Блокер.** Оракул цены Predic для BTC 15m: какая биржа и какой момент (open раунда / close / last). Сигнальные свечи должны быть с **того же** источника, иначе «заход» разъедется с MA.
3. SMA или EMA на эталонном графике заказчика? Прислать скрин настроек TV (Moving Average, тип, source).
4. База не 1$ — какое число по умолчанию и дневной лимит убытка (рекомендую лимит = 63 × base или ручной cap).
5. После 6 проигрышей: вечный halt или автосброс через N часов.
6. Комиссия Predic входит в size или сверху.
7. Нужен ли флаг «обязательный заход за MA20 предыдущей свечой» (п. 5.3).
8. Рабочие часы: 24/7 или пауза на выходные (у крипто-Predic обычно 24/7).

Не блокер для Debug-режима: 3, 4, 5, 7. Блокер только для Auto.

## 14. Архитектура (чтобы потом добавить другие стратегии)

```
UI (Start/Stop, TV, settings)
   │
   ├─ MarketData  — OHLC stream, bar-close events
   ├─ Strategy    — интерфейс: on_bar(bar) -> Signal | None
   │                 v1: MaTrendPullbackStrategy
   ├─ Risk        — martingale step, halt, balance check
   ├─ Broker      — PredicAdapter.market_buy(side, usd, client_id)
   └─ Journal     — sqlite + log file
```

`Strategy` не знает про Predic. `Broker` не знает про MA. Это и есть «логика под масштабирование», о которой писал исполнитель.

## 15. Что сознательно не делаем в v1

- Ставки сразу на 200 рынках.
- Ручное подтверждение каждого входа (заказчик: «Нет бот, хочется это автоматизировать»).
- Лимитки, сетки, усреднение кроме ×2.
- Зависимость сигнала от того, какой график сейчас на экране телефона/TV.
- Пунктир, гистограммы, третья MA.

## 16. Краткая формула для заказчика (одностраничник)

> Смотрим Bitcoin 15 минут.  
> Выше средней 200 ищем только лонги, ниже — только шорты.  
> Вход: свеча пересекла среднюю 20 и закрылась в сторону тренда (зелёная = лонг, красная = шорт).  
> Бот сразу, по маркету, ставит на Predic, что **следующая** свеча пойдёт туда же.  
> Зашло — снова с 1 $. Не зашло — ждём такой же паттерн и ставим ×2, максимум 6 раз.  
> Кнопки Start/Stop. Режим отладки рисует входы без денег.
