# Сборщик данных (V2, M0)

Круглые сутки пишет то, на чём будут проверяться бэктестер (M1) и справедливая
цена (M2): стаканы Polymarket по рынкам Up/Down, Chainlink, Binance и описание
окон. Это отдельная программа: приложение и сервер Zero Mode её не запускают, в
сборку приложения она не входит (`src/data/` исключён из пакета).

## Что записывается

Рынки: BTC, ETH, SOL, XRP × 5m, 15m, 1h, 4h, 1d — текущее и следующее окно каждой
серии и ещё 5 минут после конца окна. Окна сборщик находит сам через серии Gamma.

| Поток | Источник | Что |
|---|---|---|
| `clob` | Polymarket CLOB, канал market, 4 соединения | сообщения как пришли, без хэшей стакана: `book`, `price_change`, `last_trade_price`, `best_bid_ask`, `tick_size_change`, `new_market`, `market_resolved` |
| `chainlink` | Polymarket RTDS | цена Chainlink и TWAP-60 по четырём монетам; после каждого подключения — история за последнюю минуту |
| `fills` | RTDS, `activity` | сделки по записываемым рынкам: сторона, цена, объём, кошелёк, комиссия, транзакция |
| `binance`, `binance-book` | Binance | сделки (aggTrade) и лучшая цена (bookTicker): при смене цены — всегда, при смене только объёма — не чаще раза в 250 мс |
| `meta` | Gamma | серии и окна: токены, начало и конец, правило итога и его источник, комиссия, шаг цены, мин. объём, награды, priceToBeat и finalPrice, официальный итог; строка на каждое изменение |
| `events` | сборщик | старт и стоп, подключения и разрывы с кодом, подписки, пропуски; раз в минуту — память, CPU, задержка цикла, строки по потокам |

Хэши уровней стакана вырезаются: это случайные hex-строки, около 60% сжатых
данных, а офлайн они не нужны (`transaction_hash` остаётся).

Binance: сначала `stream.binance.com`, при отказе — официальное зеркало
`data-stream.binance.vision` (те же данные Binance.com), последним — Binance.US.
Binance.US — другая биржа: его данные идут в `binanceus` и `binanceus-book`, а
итоги по ним проверка помечает как неуверенные.

## Запуск

Нужны Node 22+ и `npm ci` в папке проекта.

```
npm run collect                              # пишет в ./collector-data до Ctrl+C
npm run collect -- --dir /srv/vespera-data   # другая папка (или VESPERA_COLLECTOR_DIR)
npm run collect -- status                    # работает ли и когда пришло последнее сообщение
npm run collect -- check today               # проверка дня UTC: today, yesterday или 2026-11-04
```

Параметры: `--assets btc,eth`, `--tfs 5m,15m`, `--gap-ms 5000` (с какой паузы
считать пропуск), `--book-sample-ms 250`, `--clob-shards 4` (соединений с CLOB),
`--json` (для `check` и `status`).

Второй сборщик в ту же папку не запустится (`collector.lock`). Ctrl+C или SIGTERM
закрывают файлы текущего часа и останавливают сбор; второй сигнал — выход сразу.

### Где держать

На любой машине, которая постоянно включена и в сети: отдельный VPS, домашний
сервер, мини-ПК. На боевом сервере Zero Mode пока не запускать: нужен отдельный
диск (ниже «Ресурсы») и решение по нагрузке (план V2, «Риски»).

systemd, `/etc/systemd/system/vespera-collector.service`:

```
[Unit]
Description=Vespera data collector
After=network-online.target
Wants=network-online.target

[Service]
User=vespera
WorkingDirectory=/opt/vespera
ExecStart=/usr/bin/node scripts/collect.js --dir /srv/vespera-data
Restart=always
RestartSec=5
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target
```

Дальше `systemctl enable --now vespera-collector`, журнал —
`journalctl -u vespera-collector -f`. Без systemd:
`nohup npm run collect -- --dir /srv/vespera-data > collector.log 2>&1 &` или
`pm2 start scripts/collect.js --name vespera-collector -- --dir /srv/vespera-data`.

Контроль: `npm run collect -- status --json` выходит с кодом 0, только если
сборщик жив и каждый источник присылал данные в последнюю минуту, — годится для
cron или внешнего мониторинга.

## Ресурсы

Замер 2026-11-04, все 20 серий:

| | |
|---|---|
| CLOB на входе | 1–4 тыс. сообщений/с, 1–2 МБ/с |
| Диск | 75–110 МБ в час: ≈ 2–2,6 ГБ в сутки, ≈ 30–40 ГБ за 14 дней |
| CPU | 20–30% одного ядра |
| Память | 135–160 МБ |

Пробный прогон 7 минут на четырёх соединениях: CLOB — 2 разрыва (1013 и 1006),
по 1,0 и 1,4 с; Chainlink — одна тишина 6,1 с, восполнена историей; Binance — без
пропусков. На одном соединении за 9 минут было 12 разрывов CLOB, самый длинный
10,8 с. Старт и итог по TWAP-60 совпали с priceToBeat и finalPrice до последнего
знака во всех окнах, где они уже были опубликованы.

## Файлы

```
collector-data/
  collector.lock               pid работающего сборщика
  state.json                   пульс раз в 10 с: для status и для пропуска «не работал»
  2026-11-04/                  день UTC
    manifest.json              по файлам: строки, первое и последнее время, размеры, sha256; пропуски; источники
    clob-17.jsonl.br           закрытый час
    clob-18.jsonl.br.part      час, который пишется сейчас
    clob-18-2.jsonl.br         вторая часть часа — после перезапуска
```

Строка — `{"rt": время получения в мс UTC, "d": сообщение}`. Сжатие — brotli
(качество 5): на этих данных почти вдвое меньше gzip при той же скорости.
Файл сжимается на лету и сбрасывается на диск раз в секунду: сбой теряет не
больше секунды, несжатых часов на диске не бывает.

Чтение:

```
brotli -dc collector-data/2026-11-04/clob-17.jsonl.br | head
```

```js
const fs = require("node:fs"), zlib = require("node:zlib"), readline = require("node:readline");
const input = fs.createReadStream(file).pipe(zlib.createBrotliDecompress());
for await (const line of readline.createInterface({ input })) { const { rt, d } = JSON.parse(line); /* … */ }
```

Python: `pip install brotli`, затем `brotli.decompress(open(path, "rb").read())`.

После сбоя следующий старт закрывает оставшийся `.part`: целые строки
сохраняются, оборванная последняя отбрасывается (в манифесте `recovered`,
`droppedLines`), а время простоя записывается пропуском `down`.

## Соединения

- **CLOB — 4 соединения.** Серии раздаются по кругу, у каждого соединения по одной
  серии 5m и 15m. Одно соединение на все 80–96 токенов Polymarket обрывал с кодом
  1013 «slow consumer» несколько раз в минуту; четыре за тот же замер — ни разу.
  Разрыв одного соединения — пропуск только его рынков (номер в поле `shard`).
- **Переподключение** — сразу, если соединение передавало данные (для коротких —
  не чаще 6 раз в минуту), иначе с паузой от 1 до 30 с.
- **Тишина.** CLOB: PING раз в 2 с, без ответа 5 с — соединение заменяется. RTDS:
  4 с без данных (Chainlink шлёт точку каждую секунду). Binance: 15 с.
- **История Chainlink.** После каждого подключения RTDS запрашивается последняя
  минута Chainlink. Если она закрыла пропуск — есть точка TWAP-60 на каждую его
  секунду по всем монетам, — проверка помечает пропуск «восполнен» и не считает
  его. У CLOB истории нет: после переподключения приходит снимок стакана (`book`),
  а изменения за время разрыва потеряны.

## Пропуски и проверка

Пропуск считается по каждому источнику (`clob` — по каждому соединению,
`chainlink`, `binance`): нет сообщений дольше `--gap-ms` (`silence`), разрыв
соединения (`disconnect`) или сборщик не работал (`down`). Пропуски идут в
`events` и в манифест дня.

`check` проверяет день:

1. **Файлы:** sha256, число строк, время, читаемость; файлы вне манифеста и
   недописанные.
2. **Пропуски** по источникам: сколько, сколько дольше 5 с (кроме восполненных),
   самые длинные.
3. **Итоги окон**, закончившихся за день: восстанавливаются из записанного и
   сравниваются с официальными из Gamma.
   - 5m, 15m, 4h (`chainlink-twap60`): TWAP-60 Chainlink в секунду начала и в
     секунду конца; заодно сверяются с priceToBeat и finalPrice.
   - 1h (`binance-1h`): цена открытия и закрытия часа по сделкам Binance.
   - 1d (`binance-1m-close`): закрытие минутной свечи в полдень ET в начале и в
     конце; равенство — 50/50.

   Итог по Binance засчитывается, только если сделки записаны по обе стороны
   границы; пропуск рядом или данные Binance.US делают его неуверенным.
   Статусы: совпало, расхождение, нет данных (окно началось до старта или попало
   в пропуск), ждёт официального итога.

Код выхода `check`: 0 — всё в порядке, 1 — ошибки в файлах или расхождения.

## Готово когда (M0)

- 14 дней сбора без пропусков дольше 5 с;
- итоги, восстановленные по Chainlink, совпадают с официальными в 100% окон;
- нагрузка машины в норме.

Ещё не сделано: исполнения из блокчейна (`OrderFilled`; пока — поток `activity`,
у которого сторона сделки верна не всегда), импорт открытых данных OpenMarket и
Polymarket-v1, выгрузка в Parquet для бэктестера.
